# pdf-to-gp-converter

Finale 로 조판된 **PDF 기타 타브 악보**를 Guitar Pro `.gp5` 로 변환하는 CLI.

PDF 의 텍스트 레이어에서 프렛 숫자·마디선·코드명·가사·연주법 표기를 좌표로 읽어
음악적 중간표현(IR)을 만들고, 그것을 `.gp5` 로 조립한다. 선택적으로 AI 보정 단계를
붙여 코드가 뜻을 몰라 흘린 표기(악센트·뮤트 노트·가사 배치)를 채운다.

```
extract (결정론적)  →  refine (AI 제안, 선택)  →  corrections (검증)  →  build
```

## 쓰는 법

```bash
uv run convert.py pdf/곡이름.pdf                       # gp/곡이름.gp5 로 저장
uv run convert.py pdf/곡이름.pdf --artist 아티스트 --tempo 90
uv run convert.py pdf/곡이름.pdf --ai                  # AI 보정까지
uv run convert.py pdf/곡이름.pdf --ir gp/곡이름.ir.json # 중간표현 덤프 (디버그)
uv run convert.py pdf/곡이름.pdf --open                # 저장 후 Guitar Pro 8 로 열기
uv run convert.py pdf/곡이름.pdf --lyrics beat          # 가사를 beat 텍스트로 (아래 참고)
uv run convert.py pdf/곡이름.pdf --tuning DADGBE --capo 2  # 대체 튜닝·카포
```

머리글에 `Capo N` 표기가 있으면 자동으로 읽는다 — `--capo` 가 그것을 이긴다.

### 가사를 어디에 담는가

`--lyrics row` (기본) 는 GP5 가사 줄에 텍스트 덩어리를 넘기고 **GP 가 음표에
분배**하게 한다 (GP7 파일에도 `<Lyrics dispatched="true">` 로 남는다). 실제 악보로
확인했고 이쪽이 낫다.

`--lyrics beat` 는 PDF x 좌표로 계산한 배정을 `Beat.text` 에 그대로 박는다. 분배
규칙에 기대지 않으므로 어긋날 수 없지만, 가사 전용 자리가 아니라 텍스트 줄에 붙는다.
다른 악보에서 `row` 의 음절이 밀리면 이쪽으로 바꾼다. 두 모드는 배타다 — 섞으면
GP 가 가사를 두 번 그린다.

결함성 경고가 하나라도 있으면 종료 코드 1 을 돌려준다. 결과를 그대로 믿지 말라는 뜻이다.

## AI 보정

`--ai` 는 `.env` 설정을 읽는다. `.env.example` 을 복사해서 채운다.

```bash
cp .env.example .env
```

설정은 OpenAI 형식 하나로 통일했다. `OPENAI_BASE_URL` 만 바꿔서 ollama·MLX·vLLM·
LM Studio·OpenRouter·OpenAI 를 쓰고, Bedrock 은 베어러 토큰으로 Converse API 를
직접 부른다 (Bedrock 의 OpenAI 호환 엔드포인트는 Anthropic 모델을 받지 않는다).

**AI 에게 이미지를 주지 않는다.** PDF 텍스트 레이어에 심볼의 정체(유니코드
코드포인트)와 정확한 좌표가 이미 다 있어서, 페이지를 렌더해 읽히면 오히려 정보를
잃는다. 덕분에 이미지를 못 보는 로컬 소형 모델도 그대로 쓸 수 있다.

### AI 가 할 수 있는 것과 못 하는 것

AI 는 네 가지만 제안할 수 있고, 모두 `tab_pdf/corrections.py` 의 검증을 통과해야
IR 에 닿는다. 버려진 제안은 전부 경고로 남는다 (`--ir` 에 이유가 적힌다).

| 제안 | 검증 |
|---|---|
| 연주법 | GP5 로 옮길 수 있는 16종만. 한 줄 표기는 그 beat 에 실제로 있는 줄만. 악센트류는 박 전체 |
| 가사 배치 | 마디 음절을 순서대로 이어붙인 글자열이 원본과 **완전히 같아야** 한다 |
| 코드명 | 추출기가 코드 행에서 실제로 읽은 이름만 |
| 보이싱 | 음정으로 검증 — 코드에 없는 음이 섞이거나 이름이 주장하는 음이 빠지면 거부 |

**음정·리듬은 AI 에게 묻지 않는다.** 프렛과 줄은 글리프 좌표에서 결정론적으로
나오므로 손댈 이유가 없다.

## 무엇이 옮겨지고 무엇이 안 옮겨지는가

옮겨진다 — 음정·줄·프렛(두 자리 프렛 포함), 리듬(잇단음표 표기가 있으면 셋잇단
포함), 쉼표, 마디·박자표(중간 변경·12/8·common/cut 포함), 못갖춘마디, 코드
다이어그램(프렛 마디 포함), 가사(다절은 GP5 가사 줄 2~5), 스트로크 방향,
해머온·풀오프·슬라이드, 악센트·마르카토·스타카토, 뮤트 노트(X 헤드),
꾸밈음(grace), 같은 프렛을 잇는 타이, 세뇨·코다·D.S. al Coda·Fine·반복 바라인,
카포·대체 튜닝.

안 옮겨진다 — 가사 늘임표(`-`), 템포 계열 지시(ritardando), 트릴·트레몰로,
테누토, 시스템(줄바꿈) 경계를 건너는 타이, 노트당 두 개 이상의 꾸밈음.
반영하지 못한 표기는 경고로 집계돼 화면에 나온다.

## 알려진 한계

- **재현성 없음** — Claude 5 계열이 `temperature` 를 거부해 온도를 고정할 수 없다.
  같은 입력에도 실행마다 보정 결과가 조금씩 다르다.
- **가사 밀집** — 보컬이 기타보다 잔 리듬을 쓰는 구간에서 beat 하나에 두 음절이
  묶인다. 두 파트의 리듬이 애초에 다른 문제라 재배치로 해결되지 않는다.
- **가사 폰트는 파일이 담지 못한다** — GP5 포맷에는 폰트·스타일 정보가 없다
  (헤더가 담는 건 용지·여백·머리말 템플릿뿐). GP8 이 자기 기본 스타일로 그리고,
  가사 줄과 beat 텍스트의 기본 폰트가 다르다. 바꾸려면 GP8 스타일시트에서 고치고
  `.gp` 로 저장한다 — 그 컨테이너는 스타일시트를 담는다
  (`Content/Stylesheets/score.gpss`). 매번 적용되게 하려면 GP8 기본 스타일시트로
  저장할 것.
- **한글 가사 전용** — 가사 판별이 한글 코드포인트 하한에 기댄다. 영문 가사 악보에는
  이 규칙이 통하지 않는다.
- **셋잇단은 SMuFL 잇단음표 숫자가 있을 때만** — 텍스트 폰트로 찍힌 '3' 은
  못 알아본다. 표기 없는 마디에 셋잇단을 허용하면 x 간격이 우연히 3등분에
  가까운 마디가 오염되는 것을 실측으로 확인해 관문을 걸었다.
- **AI 보정의 잔여 인젝션 리스크** — 제안은 코드 행 이름·beat 위치 결속·가사
  문자열 보존·이동 상한(±2 beat) 관문을 지나지만, 관문 안쪽의 왜곡(예:
  연주법 날조)은 이론상 남는다. 반영·폐기 내역이 전부 리포트에 남는다.

## 개발

```bash
uv sync
uv run pytest              # PDF·네트워크 없이 도는 것과 실제 PDF 기반이 섞여 있다
```

`pdf/`·`gp/`·`*.ir.json` 은 추적하지 않는다. 입력 PDF 가 없는 clone 에서는 실제
악보 기반 테스트가 skip 된다.
